## 장치 창과 서비스 설정

- **Devices**는 장치 목록을 비동기로 갱신하므로 조회가 느려도 창을 계속 사용할 수 있습니다. 갱신 시 정렬과 선택을 유지합니다. 추적 상태, 마지막 자세 수신 경과 시간과 상태, 배터리 및 충전 상태, 맵 보고를 표시합니다. 재연결 후에는 실제 자세를 수신한 최신 세션을 기준으로 경과 시간을 계산합니다.
- **Identify Selected**는 선택한 트래커에 식별 요청을 보냅니다. SteamVR에서도 드라이버를 통해 요청할 수 있습니다. 서비스는 SteamVR 자세 포트에 최근 자세를 보낸 트래커가 한 대로 확인되면 식별 명령을 보냅니다.
- **Factory Reset (USB)**는 확인을 받은 뒤 선택한 트래커의 시리얼로 일치하는 Windows HID 장치를 찾습니다. 트래커를 초기화하는 기능이며 USB 연결이 필요합니다.
- **Tracker Bindings**는 시리얼 기준 고정 슬롯과 연결 순서 기준 레거시 모드를 제공합니다. 고정 모드에서는 메인 트래커를 로컬에 저장할 수 있습니다. 레거시 모드로 바꿔도 저장된 고정 바인딩은 유지됩니다. 번들 SteamVR 설정의 기본 트래커 슬롯 수는 5개입니다.
- **Power / Pose Rate**에서 50 Hz 또는 60 Hz를 선택합니다. 이 값은 트래커 전원 주파수 명령과 일반 모드의 자세 전달 속도에 적용됩니다. 디버그 모드는 캡처를 위해 전달 속도를 제한하지 않습니다. 바인딩 모드나 주파수를 변경한 뒤에는 서비스를 재시작합니다.
- **Tracking lost delay (ms)**에서 SteamVR이 자세를 유효하게 보는 최대 수신 경과 시간을 설정합니다. 기본값은 100 ms에서 200 ms로 바뀌었고, GUI에서 50–2,000 ms를 지정할 수 있습니다. 적용하려면 서비스를 재시작한 뒤 SteamVR을 재시작합니다.
- **Save logs**에서 서비스 로그 저장 여부를 설정합니다. 로그를 끈 상태에서도 GUI용 장치 상태 스냅샷은 기록합니다. 별도 스크립트 `app/clear_log.cmd`는 `backups` 아래 지정된 위치의 NDJSON 및 앱 로그 파일을 삭제합니다.

## Wi-Fi 재연결과 맵 동기화

- 기본 초기화는 설정된 국가 코드를 반영하고 재연결 시점의 Unix 타임스탬프를 전송합니다. Windows의 트래커 TCP 제어 연결은 유휴 4초 후 1초 간격으로 keepalive를 보냅니다. 일반 모드는 일시적인 추적 끊김과 관련이 있던 주기적 `ATM21` 재전송을 끕니다.
- 고정 모드의 기본 ACK 초기화는 트래커 시리얼을 읽고 슬롯 번호에서 프로토콜 ID를 계산합니다. 메인 트래커는 `ATM21`로 시작합니다. 보조 트래커는 메인 초기화가 끝났으면 `ATM11`로, 아직 기다리는 중이면 `ATM21`로 시작합니다. 대기 설정은 모드 명령 뒤에 보냅니다.
- 수동 동기화는 **Tracker Bindings**에서 메인 트래커를 저장하고, **Devices**에서 연결된 보조 트래커를 선택한 뒤 **Sync with main tracker**와 **Sync Selected**를 사용합니다. 두 트래커 모두 고정 바인딩과 활성 제어 연결이 필요합니다. 보조 트래커는 슬롯 1–5에 있어야 하며, 이 슬롯은 쿼리 ID 0–4에 대응합니다. 서비스는 보조 트래커에 모드와 대기 설정, 메인 트래커 IP, 맵 로드 요청을 보냅니다.
- 메인 트래커가 저장되어 있고 고정 모드의 기본 초기화를 사용하면, 초기화된 메인·보조 연결 조합마다 자동 동기화를 한 번 요청합니다. 메인이 늦게 연결되는 경우도 포함합니다. `requested`는 제어 연결에 명령을 보냈다는 상태입니다. 맵 로드와 좌표 정렬은 트래커 및 SteamVR에서 확인해야 합니다.

## SteamVR 드라이버와 확인 범위

서비스는 트래커 자세 패킷에서 읽은 배터리와 충전 상태를 전달합니다. 드라이버는 바이너리 UTKP와 JSON 자세 패킷의 선택적 배터리 필드를 읽으며 이전 패킷도 지원합니다. 배터리 데이터가 없거나 자세 수신이 오래되면 SteamVR에서 배터리 표시를 지웁니다. 드라이버는 식별 요청도 로컬 서비스로 전달합니다. Git diff에는 `steamvr_driver/build_verify/utk_wifi_tracker`의 Windows 드라이버 패키지 갱신과 `build_verify` 내 CMake/MSBuild 중간 산출물 삭제가 포함됩니다.

이전 검증에는 Release 빌드, 배터리 및 식별 기능 검사, 동기화 요청 라우팅 모의 테스트가 포함됩니다. 이번 문서 작업에서 해당 검사를 다시 실행하지 않았습니다. 여러 트래커의 실제 맵 로드와 좌표 정렬, 자동 대기 동작, 식별 명령에 대한 기기 반응은 실기기 확인이 필요합니다.
